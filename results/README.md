# results

Generated by `../scripts/regen-results.sh`. Committed on purpose: the paper
cites these numbers, and CI regenerates them and fails on a diff, so a stale
figure cannot outlive a code change. Do not hand-edit.

**Gated.** `differential-incrate.json`, `classify.json`, `fuzz-*.json` and
`survey-hypothesis.json` come from code that ships in this crate and are
byte-identical on every host. CI fails if they drift.

**Not gated.** `differential-host.json` is a cross-language measurement, and
therefore a property of the machine that ran it — the runtime versions are
recorded inside the file. Rerunning it elsewhere legitimately produces
different bytes, so diffing it across environments would fail for the wrong
reason. What is checked everywhere is the *claim*, asserted in
`tests/acceptance.rs`: that the duplicate-key divergence exists among
decoders present on the host.

The split is not a convention but a property of how the two are produced.
`differential --in-crate-only` uses `decoder::in_crate()`, which reports
every model as `Unverified` regardless of what is installed; the full run
uses `in_crate_verified_against(present)`, which promotes a model's
provenance wherever its runtime exists. That single difference is what makes
one file diffable and the other not.

`survey-hypothesis.json` is a documentation review, not a measurement. Its
first key is the banner that says so, and `survey-hypothesis.tex` carries the
same banner as the table's caption — so the caveat cannot be lost by pasting
the table into a paper without it.

`elixir-measurement.txt` is a hand-recorded run from a GCP host with Elixir
1.17.3 / OTP 27 installed. It is a fact about that host, not about this one,
and the in-crate Elixir decoder stays `Unverified` here regardless.
